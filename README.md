# sec-deser-guard

缓存里存的对象格式被替换之后，一条外部构造的数据就能在服务端跑起任意代码：签名校验在反序列化之后，构造阶段已经执行；签名比较用普通等号，不是恒定时间；类型白名单只检查最外层，嵌套里的危险类型被放过；白名单包含可执行类型，等于没有防护；深度检测只统计列表层数，字典嵌套被绕过；深度检测到上限时返回真，超限不被拒绝；重建时对未知类型返回原值，危险对象被原样传递；策略校验不检查是否强制验签；批量加载复用上一次的验签结果，后一个输入跳过校验；解码用宽松模式，多余字段被静默忽略。guard/loader.py 是核心，tests/unit/test_loader.py 15个红。要修的是：按上面的顺序把 10 个缺陷逐个修掉。

## 运行方式

在仓库根执行：

    python -m pytest tests -q

当前预期输出为 15 failed，且没有 error。15 条测试全部会调用 guard/loader.py 中的桩，桩统一抛出 NotImplementedError；tests 目录不可修改，修复只发生在 guard/loader.py。

## 测试拆分布局

本仓库采用测试拆分布局，不使用平铺结构：

- tests/unit/test_loader.py：10 条契约测试，逐条对应 10 个缺陷。
- tests/behaviour/test_loader_edge.py：5 条边界测试，覆盖合法封装、签名错误、危险类型、深度炸弹和批次独立。
- conftest.py：把仓库根加入 sys.path，两个测试目录都通过它找到 guard 包。

unit 与 behaviour 两个目录合计 15 条测试，tests 目录整体不可修改。仓库离线可运行，无随机逻辑，也不依赖除 pytest 之外的外部库。
